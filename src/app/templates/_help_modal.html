How to Use This Application

Overview

This tool forecasts how many sprints are needed to hit a target (Items Resolved or Story Points) by running a Monte Carlo simulation against your team's historical sprint data. The flow has three steps:

  1. Data Input – upload your sprint history Excel file and set simulation parameters.
  2. Data Validation – review the sprint summary parsed from your file (can be skipped).
  3. Simulation Execution – view the forecast results and confidence levels.

Excel File Structure

The uploaded .xlsx file must contain a sheet (the first sheet is used) with one row per work item, including at least these columns:

Column Description
State Work item status. Only rows with state Resolved, Done, or Closed (case-sensitive) count toward a sprint.
Iteration Path The item's sprint/iteration, e.g. Project\Sprint 7. Only the last segment after the final \ is used as the sprint name.
Resolved Date The date the item was resolved. Used to determine each sprint's most recent activity and its recency rank.
Story Points Numeric story point estimate for the item. Blank values are treated as 0; non-numeric values will cause an error.

Any additional columns in the file are ignored. Rows are grouped by sprint to compute, per sprint, the total Items Resolved and Story Points — these historical sprint totals are what the simulation samples from.

Tips

  • Use "Exclude Latest Sprints from Sampling" to leave out in-progress or partial sprints from the random sampling pool.
  • "Team Capacity Factor" scales historical Items Resolved and Story Points to model capacity changes (e.g. 1.2 for 20% more capacity).
  • Hover the ⓘ icons next to each field for a quick description.
